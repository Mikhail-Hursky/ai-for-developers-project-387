# Мок-бэкенд на Stoplight Prism — дизайн

Дата: 2026-08-02

## Задача

Поднять мок бэкенда по существующей спецификации `spec/openapi/openapi.yaml`,
чтобы фронтенд разрабатывался против настоящих HTTP-ответов до появления
реального сервера.

## Решения

| Вопрос | Решение |
|---|---|
| Назначение | Dev-бэкенд для будущего фронтенда |
| Правдоподобность данных | Осмысленные примеры + даты, пересчитанные от текущей даты при запуске |
| Размещение | Внутри `spec/`: devDependencies и `spec/scripts/` |
| Адрес | `http://localhost:4010`, пути как в `paths` (без префикса `/api`) |
| Источник моковых данных | Единый модуль фикстур; `main.tsp` не меняется |

## Поток данных

```
main.tsp ──tsp compile──▶ openapi/openapi.yaml     (контракт, в git)
                                  │
        scripts/mock-fixtures.mjs │  (данные + даты от сегодня)
                                  ▼
                    scripts/build-mock-spec.mjs
                                  │
                                  ▼
                    openapi/openapi.mock.yaml       (dev-артефакт, в .gitignore)
                                  │
                                  ▼
              prism mock --port 4010 --errors  →  http://localhost:4010
```

`npm run mock` выполняет все три шага одной командой.

## Компоненты

| Файл | Ответственность | Зависит от |
|---|---|---|
| `spec/scripts/mock-fixtures.mjs` | Чистые функции: типы событий, окно слотов на 14 дней от текущей даты, брони, тела ошибок. Без I/O | — |
| `spec/scripts/build-mock-spec.mjs` | Читает `openapi.yaml`, раскладывает фикстуры по `examples`, подменяет `servers`, пишет `openapi.mock.yaml` | `yaml`, фикстуры |
| `spec/scripts/check-mock.mjs` | Smoke-проверка: поднимает Prism, дёргает ручки, проверяет коды и даты | `node:assert`, Prism |
| `spec/package.json` | Скрипты `mock`, `mock:spec`, `mock:check`; devDeps `@stoplight/prism-cli`, `yaml` | — |

Фикстуры отделены от вставки в спеку: первое — предметные данные (сетка слотов,
рабочие часы), второе — механика OpenAPI. Меняются независимо.

## Данные мока

- `GET /event-types` — три типа: `intro-call` (30 мин), `design-review` (60),
  `coffee-chat` (15).
- `GET /event-types/{id}` и `/slots` — именованные примеры по идентификатору типа
  события, выбираются заголовком `Prefer: example=design-review`.
- Окно слотов: `сегодня … сегодня+13`, все 14 дней присутствуют. Будни —
  10:00–18:00 UTC с шагом длительности типа; выходные — пустой `slots`; часть
  слотов детерминированно вырезана как «занятые».
- `POST /bookings` — 201 с бронью на первый свободный слот; `eventType` внутри
  совпадает с фикстурой типа.
- `GET /admin/bookings/upcoming` — три брони разных типов по возрастанию `startAt`.
- Ошибки выбираются заголовком `Prefer: code=404|409|422`.
- Флаг `--errors` включает валидацию запроса по спеке: невалидный `POST /bookings`
  сам возвращает 422 с примером `validation_failed`.

## Ограничения

Prism не хранит состояние: созданная бронь не появится в `upcoming`, повторный
`POST` на то же время не даст 409 сам по себе — только по `Prefer`. Даты
фиксируются в момент сборки мок-спеки; после смены суток мок перезапускается.
Это цена генерации мока из спеки вместо написания настоящего бэкенда.

## Проверка

`npm run mock:check` — Node-скрипт с `node:assert` (тест-раннера в проекте нет):
поднимает Prism на отдельном порту, дёргает все шесть ручек, проверяет коды
ответов, равенство `windowStartDate` сегодняшней дате, попадание всех слотов в
окно и в будущее, и что `Prefer: code=409` даёт `slot_already_booked`.

## Вне рамок

CI не затрагивается: `.github/workflows/hexlet-check.yml` помечен как
автогенерируемый и не редактируется.
