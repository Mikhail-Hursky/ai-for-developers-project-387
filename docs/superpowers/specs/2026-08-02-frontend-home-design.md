# Фронтенд: главный экран и каркас приложения — дизайн

Дата: 2026-08-02

## Задача

Поднять React-приложение календаря бронирования: главный экран с шапкой,
призывом записаться, живым списком типов встреч из мок-бэкенда и описанием
возможностей. Страницы бронирования и админки в этой итерации — заглушки,
на которые ведёт навигация.

Бэкенд не пишем: работаем против Prism-мока из `spec/`
(см. [дизайн мока](2026-08-02-prism-mock-design.md)).

## Решения

| Вопрос | Решение |
|---|---|
| Объём итерации | Главная целиком + каркас роутинга; `/booking` и `/admin` — заглушки |
| Размещение | Отдельный пакет `frontend/` в корне, рядом со `spec/` |
| Сборка | Vite 8 + React 19 + TypeScript strict |
| UI | Mantine 9 (`@mantine/core`, `@mantine/hooks`) |
| Роутинг | React Router 7, `BrowserRouter` |
| Тесты | Vitest + Testing Library |
| Адрес API | `VITE_API_BASE_URL` из `.env`, по умолчанию `http://localhost:4010` |
| Связь с моком | Прямые запросы: Prism отдаёт CORS-заголовки по умолчанию, прокси не нужен |
| Типы API | Пишем руками по `spec/main.tsp`; генератор не заводим |
| Дизайн | Свободный: крупная типографика + декоративное превью слотов |
| Тёмная тема | Не делаем |

## Структура

```
frontend/
  .env                       VITE_API_BASE_URL=http://localhost:4010  (в git)
  .env.local                 локальное переопределение, в .gitignore
  .gitignore                 node_modules, dist, .env.local
  index.html
  package.json
  vite.config.ts             плагин react + конфигурация Vitest
  tsconfig.json
  eslint.config.js
  README.md                  порядок запуска мока и dev-сервера
  src/
    main.tsx                 MantineProvider + BrowserRouter
    App.tsx                  маршруты
    theme.ts                 тема Mantine: палитра brand, шрифты, радиусы
    vite-env.d.ts            типизация ImportMetaEnv
    layout/
      RootLayout.tsx         Header + <Outlet />
      Header.tsx             логотип и навигация
    pages/
      HomePage.tsx           собирает секции главной
      BookingPage.tsx        заглушка
      AdminPage.tsx          заглушка
    features/home/
      Hero.tsx               бейдж, заголовок, подзаголовок, CTA
      SlotPreview.tsx        декоративная карточка с сеткой слотов
      EventTypes.tsx         блок типов встреч, данные из API
      Features.tsx           три карточки возможностей
    shared/api/
      types.ts               EventType, Slot, Booking, ApiError
      client.ts              обёртка над fetch
      useEventTypes.ts       хук загрузки списка типов
```

Каждый компонент отвечает за одну секцию и не знает о соседях. Статический
контент (пункты возможностей, слоты превью) лежит константами рядом с
использующим его компонентом — прокидывать его пропсами незачем.

## Маршруты

| Путь | Страница | Состояние |
|---|---|---|
| `/` | `HomePage` | Полностью реализована |
| `/booking` | `BookingPage` | Заглушка «Скоро» |
| `/booking/:eventTypeId` | `BookingPage` | Заглушка «Скоро», id пока не используется |
| `/admin` | `AdminPage` | Заглушка «Скоро» |

Все переходы — через `<Link>` React Router, без перезагрузки страницы.
Несуществующий путь ведёт на главную.

## Экран

### Шапка

Прилипающая к верху, светлая полупрозрачная подложка с размытием и нижней
границей. Слева иконка-календарь и слово «Calendar» — ссылка на `/`. Справа
«Записаться» текстовой ссылкой на `/booking` и «Админка» outline-кнопкой на
`/admin`. На узких экранах отступы сжимаются, оба пункта остаются видимыми.

### Hero

Две колонки. Слева: бейдж «Быстрая запись на звонок», заголовок в две строки
крупным весом, подзаголовок приглушённым серым, оранжевая CTA-кнопка
«Записаться →» на `/booking`. Справа — карточка с датой и сеткой слотов-пилюль
(`10:00`, `10:30`, `11:00`…), часть помечена занятыми. Карточка декоративная:
не кликается, помечена `aria-hidden` и скрыта на экранах уже `md`.

### Типы встреч

Данные из `GET /event-types`. Три состояния:

- **загрузка** — три `Skeleton` в сетке карточек;
- **ошибка** — `Alert` «Не удалось загрузить типы встреч. Проверьте, запущен ли
  мок-сервер» с кнопкой «Повторить», повторяющей запрос;
- **успех** — карточки с названием, описанием и длительностью («30 мин»),
  каждая ведёт на `/booking/{id}`;
- **пусто** — текст «Типы встреч пока не созданы».

### Возможности

Три статические карточки с иконками в ряд, на мобильных — в колонку:

1. Выбор типа события и удобного времени для встречи.
2. Быстрое бронирование с подтверждением и дополнительными заметками.
3. Управление типами встреч и просмотр предстоящих записей в админке.

### Палитра

Текст графитовый `#1a1b1e`, вторичный — приглушённый серый. Акцент — тёплый
оранжевый, зарегистрированный в теме Mantine как цвет `brand` (десятитоновая
шкала). Фон светлый холодный; мягкий градиент только в зоне hero.

## Работа с API

**Конфигурация.** Базовый URL читается из `import.meta.env.VITE_API_BASE_URL`
один раз при инициализации `client.ts`. Пустое значение — ошибка на старте с
внятным сообщением, а не молчаливые запросы по относительному пути.
`.env` хранится в git: адрес мока не секрет, и проект должен заводиться сразу
после `npm install`. Личные переопределения — в `.env.local`.

**Клиент.** Тонкая обёртка над `fetch`: подставляет базовый URL, разбирает JSON,
а на не-2xx поднимает `ApiError` с полями `code` и `message` из контракта.
Библиотеку кеширования запросов не подключаем — на один запрос это лишняя
зависимость.

**Типы.** `EventType`, `Slot`, `Availability`, `Booking`, `ApiError` описываем
руками по `spec/main.tsp`. Генерацию из OpenAPI не заводим: лишний шаг сборки
ради нескольких интерфейсов.

**Хук.** `useEventTypes()` возвращает `{ data, isLoading, error, retry }`.
Запрос уходит на монтировании; `retry` повторяет его. Ответ, пришедший после
размонтирования, отбрасывается через `AbortController`.

## Запуск

Два терминала:

```bash
cd spec && npm run mock        # http://localhost:4010
cd frontend && npm run dev     # http://localhost:5173
```

Порядок описан в `frontend/README.md`.

## Тестирование

Vitest в окружении jsdom, Testing Library, `fetch` подменяется в тестах.

| # | Проверка |
|---|---|
| 1 | Шапка рендерит «Записаться» и «Админка» со ссылками на `/booking` и `/admin` |
| 2 | Главная показывает заголовок, CTA и три карточки возможностей |
| 3 | Клик по «Админка» рендерит страницу-заглушку админки |
| 4 | Успешный ответ `/event-types` — рендерятся карточки типов с длительностью |
| 5 | Ответ 500 — рендерится алерт с ошибкой; клик «Повторить» шлёт запрос заново |

## Что осознанно не делаем

- Тёмную тему и переключатель темы.
- Прокси в `vite.config.ts` — CORS мока достаточно.
- Библиотеку состояния сервера (`react-query` и аналоги).
- Генерацию TypeScript-типов из OpenAPI.
- Реальное содержимое страниц бронирования и админки — отдельные итерации.
